# 공격 전용 RL 실험 기록

문제: 기존 사냥 조건이 엄격하고 일반 탐색·진주 수집으로 자주 전환되어, 학습한 공격 정책이 실전에서 거의 작동하지 않았습니다.

변경: v14의 탐색·수집·Queen 보호·증여는 유지하고, 짧은 개체 2~3마리의 협동 사냥 중 이동만 공유 PPO 정책으로 결정합니다. 사냥 진입 조건을 완화하고 타겟·팀 유지, 관측 누락 3라운드 유예를 추가했습니다. Queen/보호 개체 제외, 개체 길이 2~4, 350라운드 이전에만 적용합니다. 기존 긴급 생존 행동은 사냥보다 우선합니다.

## 코드와 모델

- `candidate/`: 검증 당시 C++ 코드 전체와 내장 가중치. 별도 모델 다운로드 없이 실행합니다.
- `candidate/src/attack_rl.hpp`: 관측 특징, 추론, 행동 마스크, 공격 한정 적용.
- `candidate/src/rl_weights.hpp`: checkpoint 10220의 고정 정책. 입력 522 → tanh 32 → 출력 9. 이 실험에서는 일반 이동 4개만 허용합니다. 새 RL 스프린트·분열 행동은 사용하지 않습니다.
- `candidate/src/combat.hpp`: 사냥 진입·팀 유지·종료 조건. 최대 사냥 30라운드, 진전 없음 8라운드에 종료합니다.
- `manifest.json`: 기준 커밋, 모델·소스 해시와 검증 범위.

각 개체는 독립 실행하며 공식 7×7 시야·기억·소나로 판단합니다. 모델 가중치는 공유하지만 중앙에서 모든 개체를 조종하지 않습니다. 이 폴더는 **실행 가능한 동결 정책 기록**이며, 전체 학습 데이터·체크포인트·Windows 학습 환경을 포함한 재학습 패키지는 아닙니다. 이후 production 학습의 최종 결과는 확인되지 않아 포함하지 않았습니다.

## 로컬 빌드·검사

저장소 루트에서 C++20 컴파일러로 실행합니다.

```sh
sh research/attack_rl/tests/run.sh
clang++ -std=c++20 -O2 research/attack_rl/candidate/main.cpp -o /tmp/2qrd-attack-rl
```

엔진의 봇 프로토콜 입력을 표준 입력으로 전달합니다. `--disable-rl`은 원본 휴리스틱 경로로 실행하고, `--rl-parity`는 522개 입력 특징에 대한 모델 출력을 확인합니다. `main.cpp`와 `src/entry.cpp`를 동시에 컴파일하지 마세요.

보존된 검증: RL 비활성화 시 원본 v14와 1,000턴 출력 일치, 학습 모델과 C++ 추론 수치 비교, 공격 진입·유예·보호 범위 회귀 검사. 공식 제출 WASM 연료 제한은 이 실험본에서 검증하지 않았으며, 제출 ZIP은 포함하지 않습니다.
