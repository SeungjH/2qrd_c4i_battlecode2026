# Explorer v3 — C++ 휴리스틱 봇

개체마다 독립된 C++20 프로그램이 실행됩니다. 공유 메모리 없이 현재 시야, 개체별 기억, 소나를 사용합니다.

## 제출

```sh
./package_submission.sh
```

생성되는 `dist/submission-<커밋번호>.zip`을 C++ 제출로 업로드합니다. ZIP 최상위에는 `main.cpp`, `bot.toml`만 포함됩니다. 스크립트는 커밋된 소스를 사용하며, 두 파일에 미커밋 수정이 있으면 중단합니다.

## 전략

### 1. 탐색과 반복 탈출

- 진행 방향을 유지하며 진주를 수집하고, 주변 아군과 분산합니다.
- 방문 횟수·최근 방문·관측한 벽과 통로·진주 위치를 개체별로 기억합니다.
- 4~12칸 주기의 경로를 두 번 반복하거나, 작은 구역을 계속 재방문하면 경로 탐색을 활성화합니다. 예를 들어 같은 4칸을 두 바퀴 돌면 탈출 목표를 정합니다.
- 다른 탐색 지점을 정한 뒤, 관측한 통로를 따라 BFS로 이동합니다. 목표에 도착하거나 경로가 막히거나 오래 걸리면 다시 선택합니다.
- 현재 몸통과 위험한 머리 충돌 가능성을 반영합니다. 다른 개체가 움직이는 미래까지 완전히 예측하지는 못하므로, 밀집 구역의 모든 반복을 없앤다는 보장은 없습니다.

### 2. 분열과 통로 탈출

- **모든 분열은 `SPLIT 2`**입니다. 부모 길이 L → 부모 L−2 + 새끼 2.
- 정기 분열은 기존처럼 300라운드 전, 길이 5 이상, 공간·개체 수·주변 아군·분열 간격 조건이 맞을 때 수행합니다. 300라운드부터 정기 분열을 멈춥니다.
- 통로 진입 시 입구 좌표와 진입 방향을 기억합니다. 탈출 불가능해 비상 분열을 할 때, 부모는 분열한 턴에 소나로 새끼의 예상 머리 위치와 입구 정보를 보냅니다.
- 새끼는 부모의 기억을 상속하지 않습니다. 메시지를 받으면 탈출과 경고 전달을 우선합니다. 메시지가 없더라도 좁은 통로에서 태어난 길이 2 개체는 초기 진행 방향을 따라 밖으로 나가는 것을 우선합니다.
- 벽으로 확인한 막다른 길은 부모가 경기 동안 기억합니다. 다른 개체가 소나로 받은 정보는 검증되지 않은 보고이므로 최초 보고부터 최대 80라운드 동안 회피합니다. 개체 때문에 잠깐 막힌 입구는 20라운드 동안 회피합니다. 재전달로 유효기간이 무한 연장되지는 않습니다.
- 경고는 **입구 + 진입 방향**에 적용합니다. 반대로 빠져나오는 길을 막지 않습니다. 알려진 위험 입구밖에 살아갈 길이 없으면 생존을 우선할 수 있습니다.
- 기존 부모 구출도 유지합니다. 새끼의 꼬리가 부모를 막는 경우 그 칸을 비우며, 진주 때문에 비울 수 없으면 해당 새끼 2칸만 희생할 수 있습니다.
- 길이 4 미만, 팀 한도 도달, 이미 봉쇄된 꼬리 등에서는 비상 분열이 탈출을 보장하지 않습니다.

### 3. 초·중반의 기회형 협공

- 400라운드 전, 현재 시야에 적과 아군이 있고 소나로 같은 적을 목표로 확인한 경우에만 협공합니다.
- 기본 2마리이며, 별도로 막을 세 번째 출구가 있을 때 현재 시야에서 최대 3마리를 선택합니다. ID 순서로 서로 다른 출구 차단 지점을 맡습니다.
- 적 머리로 돌진하지 않고, 두 칸 앞의 차단 지점까지 안전한 경로가 있을 때 접근합니다.
- 협공은 최대 8라운드입니다. 4라운드 동안 거리나 출구 차단 상태에 진전이 없거나 적을 놓치거나 안전한 경로가 사라지면 해산하고 8라운드 쉬었다가 재검토합니다.
- 전역 지휘자가 없고 소나도 전달에 실패할 수 있습니다. 조건이 엄격한 초기 구현이므로 항상 사냥조가 만들어지지는 않습니다.

### 4. 400라운드 이후 길이 집중

- 주변 아군끼리 소나로 길이와 역할을 교환합니다. 더 긴 아군을 지원하며, 길이가 같으면 낮은 ID를 우선합니다.
- 작은 개체가 지원을 제안하고 큰 개체가 수신 확인을 보내야만 의도적인 희생이 가능합니다. 큰 개체는 한 번에 한 공여자만 맡습니다.
- 최초 구현은 길이 2~12의 공여자 전체 몸이 보이고, 예상 진주까지 경로가 5칸 이내이며, 회수 공간·적 접근·남은 시간이 허용하는 경우로 제한합니다.
- 희생 직전 다시 조건을 확인하고, 벽 → 자기 몸 → 아군 몸통 순으로 가능한 충돌을 선택합니다. **아군 머리를 희생 대상으로 선택하지 않습니다.**
- 수신자는 예상 진주 위치를 기억하고 회수를 우선합니다. 두 개체가 합의한 지원 중에는 일반적인 아군 분산보다 접근·회수를 우선합니다.
- 사망 시 길이의 절반을 올림한 수만큼 진주가 됩니다. 직접 합체가 아니며 전부 회수하지 못할 수도 있습니다.

### 유지하는 제약

- **부스터 금지:** 모든 이동 명령의 방향은 정확히 한 글자입니다.
- **분열 크기 2 고정.**
- 포털은 개체당 최대 2회입니다. 양쪽 경계를 알고 출구가 현재 시야에 있어 안전을 확인할 수 있는 경우를 우선하며, 확인된 탈출 방법이 전혀 없으면 미확인 포털을 최후 수단으로 시도할 수 있습니다.
- 소나는 최대 네 방향으로 보냅니다. 상태·경고·탈출 임무·지원 제안/동의·협공 목표를 64비트에 담습니다. 벽과 다른 개체가 전달을 막을 수 있습니다. 엔진은 발신자를 인증하지 않으며, 중요한 합의에는 최근 상태와 현재 보이는 아군을 추가로 확인합니다.

## 리플레이에서 확인할 표시

`INDICATOR v3` 뒤에 선택 이유가 표시됩니다.

| 표시 | 의미 |
| --- | --- |
| `EXPLORE`, `NAVIGATE` | 일반 탐색, 기억한 목표로 이동 |
| `COURIER_ESCAPE` | 통로에서 탈출하며 경고 전달 |
| `HUNT_BLOCK` | 협공의 차단 지점으로 이동 |
| `DONOR_APPROACH` | 지원을 제안한 공여자의 접근 |
| `RECEIVE_APPROACH`, `RECEIVE_PEARLS` | 수신자의 접근·진주 회수 |
| `DONATE_CONFIRMED` | 수신 확인과 최종 검사 후 희생 |
| `SCOUT_SPLIT_2`, `RESCUE_SPLIT_2`, `LAST_RESORT_SPLIT_2` | 정기 분열, 부모 구출, 최후 분열 |

`goal`은 y×64+x로 인코딩한 탐색 목적지, `peer`는 지원 대상 ID, `enemy`는 협공 대상 ID, `entry`는 기억한 입구입니다. -1은 지정되지 않았다는 뜻입니다.

## 검증

### 로컬 행동 검사

```sh
./tests/run.sh
```

C++20 컴파일러와 Python 3만 필요합니다. 컴파일 결과는 임시 디렉터리에 생성되고 종료 시 정리됩니다. 반복 탈출, 방향별 입구 경고, 경고 만료, 새끼 임무 인계, 지원 동의·회수 위험, 동시 공여자 제한, 협공 합의·시간 제한, 단일 이동·2칸 분열·부모 구출 등을 검사합니다.

공식 엔진 통합 검사는 `unswbc 1.2.2`가 설치된 Python으로 실행합니다.

```sh
clang++ -std=c++20 -O2 main.cpp -o /tmp/explorer-v3
UNSWBC_NO_UPDATE=1 UNSWBC_NO_VSCODE=1 python3 tests/engine_trap.py /tmp/explorer-v3
```

이 테스트는 인공 통로에서 정기 분열을 제외하고 비상 분열을 검사하기 위해 봇 입력 라운드를 350부터 시작시킵니다. 부모의 분열 턴 소나가 새끼에게 전달되고 입구 경고가 재전달되는지 확인합니다.
