# Explorer v11 — C++ 휴리스틱 봇

각 드래곤이 같은 프로그램을 독립 실행합니다. 자기 시야·이동 기억·소나로 협력합니다. RL은 사용하지 않습니다.

## 제출

`./package_submission.sh` → **`dist/2qrd_v11.zip`**. 커밋된 `main.cpp`, `bot.toml`만 포함하며 4 MB 미만입니다. ZIP은 GitHub에 올리지 않습니다.

## 변경 사항

- **희생 증여 우선 수정:** 점유된 수신자 머리를 목적지로 삼는 대신, 관측한 길을 탐색해 집결 지점 주변으로 접근합니다. 맨해튼 거리가 잠시 늘어나는 우회도 허용합니다. 접근 실패 판단은 12→32라운드, 재시도 대기는 12→4라운드입니다.
- 안전하게 전진할 수 있는 통로에서도 증여하도록 수신자의 즉시 출구 조건을 2→1개로 바꿨습니다. 회수 거리·공간·시간·주변 적 검사는 유지합니다. 중립 개체가 공여 대기열을 막지 않도록 실제 공여 역할만 순서를 경쟁합니다.
- 최근 길이 보고와 눈으로 확인한 머리가 있으면 추가 STATUS 수신을 요구하지 않습니다. 수신자는 OFFER뿐 아니라 공여 역할 STATUS로도 회수를 준비합니다. 초기 소나 방향과 짧은 순환이 계속 엇갈리는 문제를 줄이기 위해 수신자는 3라운드마다 여러 방향으로 위치를 알립니다.
- **공식 Queen이 최우선입니다.** 길이가 더 큰 아군이 Queen을 대체하지 않습니다. Queen용 공여 길이 상한은 R280부터 4, R330부터 6, R350부터 12입니다. Queen보다 긴 수집병도 공여할 수 있습니다. 일반 최장 개체용 공여 상한은 12입니다. 희생 순간의 로컬 회수 안전 검사를 따로 적용합니다. Queen 사망이 확인되었거나 아직 공식 ID를 모르는 경우에는 최장 개체 전략을 사용합니다. 침묵을 사망으로 판정하지 않습니다.
- 최장 개체 수신자는 R350부터 길이 4로도 증여를 받습니다. 64라운드 동안 작은 길이 차이로 수신자를 교체하지 않으며, 4칸 이상 큰 후보는 교체할 수 있습니다. 수신자는 길이 4부터 긴 개체 생존 검사와 포털 금지를 적용합니다.
- **먹이 양보:** OFFER/ACCEPT로 본 증여 몸통은 10라운드 예약합니다. 수신자는 보이는 증여 진주를 우선 회수합니다. 공식 Queen의 신선한 집결 신호가 있으면 그 구역의 진주도 예약합니다. 일반 최장 개체의 구역 전체를 금지하지는 않으며 실제 증여 예약을 강제합니다. R280 이후 다른 개체의 일반 이동과 경로 탐색에서 예약 진주를 제외합니다. 시야에서 공식 Queen 머리를 확인하면 소나가 없어도 주변 먹이를 양보합니다.
- **Queen 거점은 스폰 지역입니다.** 첫 머리 위치를 저장하고, 주변 사각 영역에서 식사와 생존을 우선합니다. 반경은 최소 4, 성장에 따라 `length/4+2`입니다. 거점 바깥 먹이·수익 구역을 따라가지 않습니다. 적 접근이나 공간 부족이면 거점을 해제하고 근처 안전 공간으로 이동할 수 있습니다.
- 집결 중심과 실제 머리 위치를 별도로 소나 중계합니다. QUEEN 패킷 bit 26은 집결 신호이며 실제 머리 보고를 덮어쓰지 않습니다. 원본 시각을 유지하고 20라운드가 지난 집결 신호는 버립니다.
- **제한적 2칸 이동:** R350 이후 길이 5 이상인 공여자가 집결하러 이동할 때만 사용합니다. 시작 길이 기준 무료 이동 2칸으로 길이를 소모하지 않습니다. Queen·수신자·근처 아군·시야 내 적·포털·몸 기억이 불완전한 경우는 제외합니다. 두 단계의 벽·점유·몸 충돌과 마지막 생존 공간을 검사하고, 수신자 근처에서는 한 칸씩 움직입니다.
- **갈림길 탐색:** 초반 길이 5–8 개체가 머리·꼬리 모두 안전한 갈림길에 있으면 2칸 자식을 다른 방향으로 보냅니다. ESCAPE 예약 값 4094로 첫 방향을 전달합니다. 탈출 개체도 갈림길에서 직진만 고집하지 않고 보이는 공간과 출구를 비교합니다.

## 검증

최종 소스로 6개 맵 × 4개 시드 × 양쪽 진영, 총 48경기를 병렬 실행했습니다. v10 상대 23승 25패였습니다. 희생 동작의 개선과 별개로 전체 승률 향상은 입증되지 않았습니다.

- 6개 증여 배치 모두 공여자 6마리의 실제 희생을 확인했습니다. Queen은 초기 길이 8에서 최종 17·17·19, Queen 사망 후 지정 최장 개체는 4에서 11·17·11로 성장했습니다. 각 배치에서 지정 수신자의 증여 진주 섭취는 9개 또는 8개였고, 다른 개체의 증여 진주 섭취는 0개였습니다.
- 제출용 WASM 환경에서 500라운드 실행을 완료했고 시간 초과·실행 오류가 없었습니다. 최대 연산량은 턴당 7.1M으로 100M 제한 이내였습니다.
- 기존 전략·행동 회귀 검사에 단일 출구 증여, 길이 4 수신자, 스폰 거점 200턴, 2칸 이동과 이동 후 소나 좌표·길이 검사를 추가했습니다.
- 공식 엔진의 공여 통합 테스트는 자연 진주를 미리 배치하지 않고, 실제 생산 봇으로 공여자 6마리를 운용합니다. 원본·좌우 반전·상하 반전 배치 모두 실제 희생, 지정 수신자의 증여 진주 섭취, 수신자의 500라운드 생존을 검사합니다. 별도의 Queen 사망 후 최장 개체 수신 테스트도 포함합니다.
- 공식 엔진에서 길이 6 공여자의 2칸 이동 후 실제 좌표와 길이 6 유지도 확인합니다. 이 테스트의 원거리 Queen 길이 보고는 통신을 주입해 이동 비용을 분리 검증합니다. 공여 통합 테스트는 실제 소나만 사용합니다.
- 전달받은 M861114에서 후반 DONOR_SEEK 1,334회 대비 의도적 희생 5회로 확인됐습니다. 리플레이의 공개 맵은 모든 TILE이 `0 0`이어서 당시 진주 생성 조건과 상대 소스까지 그대로 재현한 대전은 아닙니다.
- 16칸 공여자가 밀집한 `--large` 실험 배치는 회수·생존 검사를 통과하지 못했습니다. 공여 상한 24와 강제 순환 이동·시야 밖 진주 기억 실험은 제외하고, 검증된 상한 12를 유지합니다. 이 진단용 배치는 테스트 파일에 남겨 두었습니다.
- 소나가 도달하지 않은 개체나 오래된 정보까지 독점 회수를 보장할 수는 없습니다. 로컬 안전 검사가 실패한 공여자는 죽지 않고 접근을 재시도합니다. 실제 상대와 맵별 추가 검증은 계속 필요합니다.
