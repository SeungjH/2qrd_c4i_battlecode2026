# Explorer v12 — C++ 휴리스틱 봇

각 드래곤이 같은 프로그램을 독립 실행하며 시야·이동 기억·소나로 협력합니다. RL은 사용하지 않습니다.

## 제출

`./package_submission.sh` → **`dist/2qrd_v12.zip`**. 커밋된 `main.cpp`, `bot.toml`만 포함하고 4 MB 미만입니다. ZIP은 GitHub에 올리지 않습니다.

## v11에서 수정한 문제

- **초반 수집병의 먹이 양보 해제:** Queen 주변 진주·스폰 집결 구역의 예약은 R280부터 적용합니다. 초반 수집병이 Queen 근처라는 이유만으로 진주를 포기하지 않습니다. 실제 증여 진주 예약은 유지합니다.
- **Queen 상태를 모르면 다른 개체에게 희생 금지:** Queen이 살아 있는지 알 수 없는데 일반 최장 아군에게 증여하던 경로를 막았습니다. Queen 사망이 확인된 뒤에는 최장 개체용 증여를 허용합니다. 위치·길이 정보가 부족하면 수집을 계속합니다.
- **Queen 사망 신호 수신 수정:** Queen을 처음 알리는 신호가 사망 보고일 때도 처리합니다. 사망 시각을 다른 최장 개체의 최신 보고 시각과 비교하지 않고, 해당 Queen의 마지막 생존 보고와 비교합니다. 더 최신 생존 보고가 있으면 오래된 사망 신호는 거절합니다.
- **사망 직후 증여 좌표 보존:** 공여자의 STATUS가 잠시 남아 있어도 실제 머리가 보이지 않으면 빈 몸통 관측으로 진주 좌표를 지우지 않습니다. 실제 진주가 확인된 뒤 회수합니다.

Queen의 스폰 거점 보호·고정 ID 우선·무료 2칸 공여 이동·갈림길 분열·함정 공유·공격은 v11 로직을 유지합니다. 스폰 제한 완화, 더 깊은 몸 이동 예측, 꼬리 순환 선호, 광범위한 사망 신호 반복 전파는 비교 성적이 낮아 제외했습니다.

## 대전 검증

최종 소스 기준 6개 맵 × 양쪽 진영. 기본 시드는 101/202/303/404, 추가 시드는 505/606입니다.

|상대|기본 48경기|추가 24경기|합계|
|---|---:|---:|---:|
|v11|25승 23패|15승 9패|**40승 32패 (55.6%)**|
|v10|25승 23패|13승 11패|**38승 34패 (52.8%)**|

관측 성적은 소폭 우세지만, 이 표본만으로 확실한 승률 향상이나 온라인 상대에 대한 우위를 주장하지 않습니다. 특히 Trophy의 초반 수집 회귀와 큰 Queen·수신자의 구조 분열/사망은 아직 남아 있습니다. 로컬 Autarky/Dilemma 초기 Queen 배치는 온라인 리플레이와 다를 수 있습니다.

## 동작 검증

- 전략·프로세스 행동 검사 통과. 새 검사는 초반 진주 허용/후반 예약, 미확인 Queen 상태에서 희생 금지, 사망 확인 후 희생 허용, 오래된 사망 보고 거절, 공여자의 오래된 STATUS가 남은 실제 진주 회수를 검사합니다.
- 공식 엔진의 Queen 증여 배치 3개 모두 실제 공여 6회, 지정 수신자의 증여 진주 섭취 9개, 다른 개체의 증여 진주 섭취 0개를 확인했습니다. Queen 초기 길이 8 → 최종 17/17/19, 500라운드 생존.
- Queen이 관측되지 않은 채 처음부터 죽은 배치 3개에서는 사망을 임의로 추측하지 않아 일반 최장 개체에게 희생하지 않았습니다. 이는 증여 성공 테스트가 아닌 잘못된 증여 방지 테스트입니다. 사망 신호 이후의 증여 동작은 전략·프로세스 행동 검사로 별도 확인합니다.
- 무료 2칸 이동·진주 회수·분열 구조·꼬리 공격·함정 신호 전달·고정 Queen 승리 조건의 공식 엔진 검사 통과.
- 제출용 WASM 환경에서 500라운드 완료, 실행 오류·시간 초과 없음. v12 최대 연산량 7.0M/턴으로 100M 제한 이내.

소나가 모든 개체에게 전달되는 것은 아니며, 시야 밖 증여 진주 독점 회수와 혼잡한 대형 수신자의 생존은 보장하지 않습니다.
