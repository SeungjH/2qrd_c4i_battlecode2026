# Explorer v9 — C++ 휴리스틱 봇

각 드래곤이 같은 C++20 프로그램을 독립 실행합니다. 자기 7×7 시야, 이동 기억, 소나만 사용합니다. **RL과 스프린트는 사용하지 않습니다.**

## 제출

`./package_submission.sh` → **`dist/2qrd_v9.zip`**. 최상위 `main.cpp`, `bot.toml`만 포함하며, 커밋되지 않은 소스나 4 MB 이상 ZIP은 거부합니다. ZIP은 GitHub에 올리지 않습니다.

## 가장 중요한 수정: 공식 queen

- 공식 queen은 팀의 고정 ID **0 또는 1**입니다. 팀 소속은 관측·소나로 확인합니다. 더 긴 자식이나 아군이 생겨도 queen ID는 바뀌지 않습니다.
- 500라운드의 순위는 **queen 길이 → 최장 생존 개체 길이 → 팀 총 길이** 순서입니다. 팀 전멸은 먼저 경기를 끝냅니다. 죽은 queen은 길이 0입니다.
- v8의 `queenId`는 최장 아군을 동적으로 고른 값이었습니다. v9은 `officialQueenId`와 `feedTargetId`를 분리합니다. 살아 있는 공식 queen의 최신 보고가 있으면 길이 2여도 증여를 우선합니다.
- queen은 초반부터 일반 분열·공격 분열·머리 교환·포털 진입·수익형 함정 진입을 하지 않습니다. 안전한 순환을 탐색 부족으로 간주해 강제로 벗어나게 하지 않습니다.
- 비상 분열은 계속 가능합니다. 원래 머리 2칸을 남기는 역방향 탈출에서도 **원래 부모 ID가 queen**이며 긴 자식이 이를 계승하지 않습니다. queen을 자식에게 넘긴다는 가정으로는 승리 조건을 지킬 수 없습니다.
- 관측·소나가 끊겼다는 이유만으로 queen이 죽었다고 단정하지 않습니다. 최신 좌표에서 한 칸 이동으로 가능한 위치들이 모두 현재 시야에 들어오는데 queen이 관측되지 않을 때만 사망을 확인·중계합니다. 이 판정은 우리 queen의 한 칸 이동·포털 금지 정책을 전제로 합니다.

## 중·후반 증여

- **R280–329:** 길이 2–4 공여자. **R330–399:** 2–6. **R400 이후:** 2–12. 실제 queen은 자신보다 긴 공여자도 받을 수 있으며, queen 자신은 공여자가 되지 않습니다.
- 최신 길이·좌표와 실제 가까운 머리를 확인하고, 사체 진주의 회수 경로·queen이 머물 공간·두 개 이상 출구·주변 적을 확인한 뒤 희생합니다. 벽이나 자기 몸을 이용하고 아군 머리는 들이받지 않습니다.
- 길이 4 이하가 실제 queen 2칸 이내에서 모든 사체 진주를 회수할 수 있으면 직접 증여합니다. 그 밖에는 OFFER/ACCEPT 확인 또는 R330 이후 근접 재시도 조건을 사용합니다.
- 한 공여자를 받을 때 다른 공여자는 길을 비웁니다. queen의 다음 진행 칸을 보호하고, 주변·예약 진주를 다른 아군이 먹는 것을 억제합니다. 소나가 막히거나 적·몸통이 움직이면 독점 회수는 보장할 수 없습니다.
- queen은 R300부터 넓고 출구가 있는 공간을 집결 장소로 활용합니다. 공여자가 12라운드 동안 접근에 진전이 없으면 12라운드 수집으로 복귀합니다. 실제 진주가 생긴 것을 확인한 뒤 회수하며, 실패한 대기는 해제합니다.
- queen의 사망이 확인되면 최장 개체를 위한 기존 증여를 보조 전략으로 사용합니다. queen ID를 아직 모르는 개체도 이 보조 전략을 사용합니다.

## 탐색·공격·위험 회피

- 소형 개체의 일반 분열은 꼬리 2칸이며 R300부터 중단합니다. 큰 맵에서는 더 넓게 퍼지되 모든 개체가 동시에 미탐색 경계로 향하지 않도록 정찰 역할을 나눕니다. 아군 밀집 시 분산 점수를 높입니다.
- 보이는 진주의 실제 우회 경로, 반복 생성 수익 구역·포털 출구 공유, 방향별 함정 경고 중계를 유지합니다. queen과 후반 긴 개체는 포털에 들어가지 않습니다.
- 긴 개체는 움직이는 자기 몸을 반영한 최대 6수 탐색을 사용하며, 길찾기·임무 이동도 이 생존 검사를 통과해야 합니다. 시야 밖의 점유·미관측 지형에는 불확실성이 남습니다.
- 협공은 소형 2–3마리, 관측상 충분히 큰 상대, 차단할 출구 수를 확인해 시작합니다. 바로 먹을 안전한 진주를 포기하는 공격은 queen 호위 상황으로 제한합니다. 최대 30라운드·무진전 8라운드 후 해제합니다.
- 꼬리 2칸 매복과 queen 근처 소형 호위병의 유리한 머리 교환을 유지합니다. queen은 직접 교환하지 않습니다. 공여 역할의 소형 개체도 필요한 호위 교환에 참여할 수 있습니다.

## 소나

64비트 구성은 기존과 같습니다: 표시 8 / 팀 1 / 종류 3 / 원본 ID 16 / 원래 라운드 9 / 데이터 27. 네 방향에 상태·목표·위험·임무·자원 정보를 나눠 전송합니다. 공식 queen 정보는 길이 2부터 중계하고, 확인된 사망은 목표 보고의 길이 0으로 전파합니다. 소나 경로가 막히면 즉시 팀 전체에 전달되지 않습니다.

## 검증 — 2026-10-02

공식 **unswbc 1.2.3**에서 v8과 여섯 맵·시드 101/202/303/404·양 진영, 48경기를 병렬 실행했습니다.

| 맵 | v9 승 / 8 | v9 queen 생존 / 8 |
|---|---:|---:|
| Default | 4 | 1 |
| Dilemma | 3 | 0 |
| Portals | 3 | 0 |
| Trauma | 8 | 6 |
| Devil | 3 | 0 |
| Trophy | 3 | 0 |

**24승 24패**, queen 최종 생존은 **7 대 0경기**였습니다. 전체 승률 향상으로 해석할 수 없으며, Trauma 외 queen 생존은 부족합니다. 상대 상위팀과의 재대결 결과가 아닙니다.

Trauma 시드 101의 v9 A는 queen이 R200 길이 11, R350 길이 19, 종료 길이 **29**로 성장했습니다. 계획된 증여 3회가 queen을 향했고 진주 **5개를 queen이 회수**, 이 증여 진주를 다른 아군이 가져간 경우는 관측되지 않았습니다. 같은 조건의 공식 WASM 샌드박스도 queen **29 대 0**으로 승리했습니다. CPU 포인트 중앙값 **5.3M**, 최대 **6.9M / 제한 100M**이었습니다.

```sh
./tests/run.sh
# 아래 검사는 unswbc 1.2.3이 설치된 Python으로 실행
clang++ -std=c++20 -O2 main.cpp -o /tmp/explorer-v9
python3 tests/engine_scoring.py
python3 tests/engine_donation.py /tmp/explorer-v9
python3 tests/engine_donation.py /tmp/explorer-v9 small
python3 tests/engine_reverse.py /tmp/explorer-v9
python3 tests/engine_ambush.py /tmp/explorer-v9
python3 tests/engine_trap.py /tmp/explorer-v9
```

고정 queen이 더 긴 아군보다 우선하는지, queen의 분열·포털·증여 금지, 통신 단절과 사망 구분, 길이 2 queen의 R300 증여 회수, 역방향 자식이 queen을 계승하지 않는지 등을 확인합니다.
